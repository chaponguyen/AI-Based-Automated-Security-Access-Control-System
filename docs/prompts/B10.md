# Prompt B10 — Kiểm thử tích hợp và đo số liệu (giao cho A6: QA và Tài liệu)

Dán nguyên khối dưới đây vào công cụ (mở công cụ ở thư mục gốc project):

```
Đọc AGENTS.md rồi docs/context/ (PROJECT_BRIEF, DB_SCHEMA, API_CONTRACT, DECISIONS_LOG, PROGRESS_LOG) trước khi viết code. Mở docs/reports/B10.md để xem checklist và docs/plan/MO_TA_CONG_VIEC.md mục B10 để xem đặc tả chi tiết từng checkpoint.

Bạn là A6 (QA và Tài liệu). Việc: B10 — Kiểm thử tích hợp và đo số liệu.
Mục tiêu: Đo độ chính xác, FAR/FRR, thời gian xử lý, chống giả mạo, độ trễ mặt đến loa, cảnh báo giả và bỏ sót.
Chỉ được sửa: docs/reports/, scripts/ (chỉ script đo và test). Không được sửa: mọi code nghiệp vụ (chỉ báo lỗi).

Các checkpoint, làm lần lượt, mỗi lần đúng một checkpoint:
CP-01 Chuẩn hóa bộ test và kịch bản  [kiểm tra: bảng số lượng ảnh trong báo cáo]
CP-02 Đo độ chính xác theo ngưỡng  [kiểm tra: bảng và biểu đồ FAR/FRR; đề xuất ngưỡng]
CP-03 Đo thời gian xử lý  [kiểm tra: bảng thời gian; ghi cấu hình máy]
CP-04 Đo chống giả mạo  [kiểm tra: bảng và danh sách ảnh giả lọt qua]
CP-05 Tổng hợp  [kiểm tra: dùng được làm Chương 3]
CP-06 Nghiệm thu thời gian thực end-to-end  [kiểm tra: bảng số liệu và nhận xét đưa vào Chương 3]

QUY TẮC BÁO CÁO THEO CHECKPOINT (bắt buộc, quan trọng hơn tốc độ):
1. Làm đúng MỘT checkpoint rồi dừng lại (một bảng, một nhóm cột, một hàm, một route hoặc một component).
2. Tự kiểm tra tối thiểu (py_compile, import, chạy thử nhỏ).
3. NGAY LẬP TỨC ghi nhật ký, trước khi git commit và trước khi sang checkpoint kế:
   python scripts/log_checkpoint.py B10 CP-xx --file <file vừa sửa> --auto --did "<đã làm gì, nêu tên bảng, cột, hàm cụ thể>" --why "<vì sao làm vậy>" --check "<đã kiểm tra thế nào>" --todo "<bước kế tiếp>"
   (--auto tự tìm số dòng đã viết. Có thể lặp --file nếu sửa nhiều file.)
4. Rồi mới: python scripts/agent_commit.py A6 "[B10] CP-xx <mô tả> - A6"
5. Cấm gộp nhiều checkpoint rồi viết báo cáo sau, cấm để báo cáo đến cuối việc.
6. Thấy sắp hết token hoặc quota: dừng việc mới và chạy
   python scripts/log_checkpoint.py B10 --handoff --note "<đang dở gì, file và dòng nào, bước kế tiếp>"

Tiêu chí xong: Có bảng số liệu thật cho Chương 3.
Lưu ý riêng: Ghi cấu hình máy khi đo.
Không đổi tên hàm hay route đã có; nếu buộc phải đổi thì DỪNG, ghi đề xuất vào DECISIONS_LOG.md mục "Đề xuất đổi contract" và hỏi tôi; chỉ sau khi tôi duyệt mới cập nhật API_CONTRACT.md hoặc DB_SCHEMA.md trong cùng lần commit.

CHẾ ĐỘ SONG SONG: các Agent khác có thể đang làm cùng lúc, mỗi Agent ở một worktree riêng (xem docs/plan/CHAY_SONG_SONG.md).
- Commit bằng: python scripts/agent_commit.py A6 "<commit message>" (chỉ add đúng thư mục của bạn). KHÔNG dùng git add -A.
- Cần hàm hoặc endpoint của Agent khác mà chưa có: dùng stub hoặc mock theo API_CONTRACT.md, ghi TODO, không viết hộ phần của họ.
- Muốn đổi chữ ký hàm, route hoặc schema: DỪNG, ghi vào DECISIONS_LOG.md mục "Đề xuất đổi contract" rồi hỏi tôi. Không tự đổi.
- Không sửa file ngoài thư mục được phép, kể cả sửa lỗi nhanh; hãy báo lỗi cho tôi.
```

Nếu phiên bị ngắt, dùng prompt tiếp tục trong docs/prompts/00_PROMPT_CHUNG.md.
