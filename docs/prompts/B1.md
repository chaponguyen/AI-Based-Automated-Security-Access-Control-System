# Prompt B1 — Cơ sở dữ liệu: 3 bảng + Alembic (giao cho A2: Backend và DB)

Dán nguyên khối dưới đây vào công cụ (mở công cụ ở thư mục gốc project):

```
Đọc AGENTS.md rồi docs/context/ (PROJECT_BRIEF, DB_SCHEMA, API_CONTRACT, DECISIONS_LOG, PROGRESS_LOG) trước khi viết code. Mở docs/reports/B1.md để xem checklist.

Bạn là A2 (Backend và DB). Việc: B1 — Cơ sở dữ liệu: 3 bảng + Alembic.
Mục tiêu: Định nghĩa 3 bảng users, face_embeddings, access_logs đúng docs/context/DB_SCHEMA.md và sinh migration đầu tiên.
Chỉ được sửa: backend/database/models.py, backend/migrations/. Không được sửa: backend/ai/ (chỉ gọi hàm), frontend/, embedded/.

Các checkpoint, làm lần lượt, mỗi lần đúng một checkpoint:
CP-01 Bảng users: id, full_name, age, apartment_number (có index)  [kiểm tra: py_compile]
CP-02 users: status + CheckConstraint (active/inactive), created_at, property user_code  [kiểm tra: py_compile]
CP-03 Bảng face_embeddings: id, user_id (FK, xóa theo user), embedding ARRAY(Float)  [kiểm tra: py_compile]
CP-04 face_embeddings: quality, model_version, created_at + relationship với users  [kiểm tra: import models không lỗi]
CP-05 Bảng access_logs: user_id (cho phép NULL), similarity, liveness, decision, reason, timestamp (index)  [kiểm tra: import models không lỗi]
CP-06 Khởi tạo Alembic; env.py đọc DATABASE_URL và dùng Base.metadata  [kiểm tra: alembic --help chạy được]
CP-07 Sinh migration đầu tiên, đối chiếu từng cột với DB_SCHEMA.md  [kiểm tra: đọc file migration]

QUY TẮC BÁO CÁO THEO CHECKPOINT (bắt buộc, quan trọng hơn tốc độ):
1. Làm đúng MỘT checkpoint rồi dừng lại (một bảng, một nhóm cột, một hàm, một route hoặc một component).
2. Tự kiểm tra tối thiểu (py_compile, import, chạy thử nhỏ).
3. NGAY LẬP TỨC ghi nhật ký, trước khi git commit và trước khi sang checkpoint kế:
   python scripts/log_checkpoint.py B1 CP-xx --file <file vừa sửa> --auto --did "<đã làm gì, nêu tên bảng, cột, hàm cụ thể>" --why "<vì sao làm vậy>" --check "<đã kiểm tra thế nào>" --todo "<bước kế tiếp>"
   (--auto tự tìm số dòng đã viết. Có thể lặp --file nếu sửa nhiều file.)
4. Rồi mới: python scripts/agent_commit.py A2 "[B1] CP-xx <mô tả> - A2"
5. Cấm gộp nhiều checkpoint rồi viết báo cáo sau, cấm để báo cáo đến cuối việc.
6. Thấy sắp hết token hoặc quota: dừng việc mới và chạy
   python scripts/log_checkpoint.py B1 --handoff --note "<đang dở gì, file và dòng nào, bước kế tiếp>"

Tiêu chí xong: Migration có đúng 3 bảng, đủ cột. Bạn tự chạy alembic upgrade head và thấy 3 bảng trong pgAdmin.
Lưu ý riêng: KHÔNG chạy alembic upgrade. Không tạo cột user_code.
Không đổi tên hàm hay route đã có; nếu buộc phải đổi thì DỪNG, ghi đề xuất vào DECISIONS_LOG.md mục "Đề xuất đổi contract" và hỏi tôi; chỉ sau khi tôi duyệt mới cập nhật API_CONTRACT.md hoặc DB_SCHEMA.md trong cùng lần commit.

CHẾ ĐỘ SONG SONG: các Agent khác có thể đang làm cùng lúc, mỗi Agent ở một worktree riêng (xem docs/plan/CHAY_SONG_SONG.md).
- Commit bằng: python scripts/agent_commit.py A2 "<commit message>" (chỉ add đúng thư mục của bạn). KHÔNG dùng git add -A.
- Cần hàm hoặc endpoint của Agent khác mà chưa có: dùng stub hoặc mock theo API_CONTRACT.md, ghi TODO, không viết hộ phần của họ.
- Muốn đổi chữ ký hàm, route hoặc schema: DỪNG, ghi vào DECISIONS_LOG.md mục "Đề xuất đổi contract" rồi hỏi tôi. Không tự đổi.
- Không sửa file ngoài thư mục được phép, kể cả sửa lỗi nhanh; hãy báo lỗi cho tôi.
```
